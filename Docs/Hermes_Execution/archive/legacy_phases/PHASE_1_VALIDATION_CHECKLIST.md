## API Contract Checks
- [ ] `/query/check` never executes SQL.
- [ ] `/query/check` returns Safety Report.
- [ ] `/query/check` returns visible `confirmation_code` for high-risk.
- [ ] `confirmation_code` is 4 numeric digits.
- [ ] `confirmation_code` is generated by backend, not LLM.
- [ ] `confirmation_code` is bound to `check_id + SQL hash + target + expiry`.
- [ ] `/query/execute` requires `check_id`.
- [ ] `/query/execute` requires Yes decision.
- [ ] `/query/execute` rejects missing/invalid/expired code for high-risk.
- [ ] `/query/execute` returns `DB_PERMISSION_DENIED` if selected credential lacks permission.
- [ ] `/manual-sql/execute` is not primary Phase 1 right-sidebar contract.

## UI Checks
- [ ] UI is chat-first.
- [ ] Left sidebar has session history, new session, settings, model connection, database connection.
- [ ] Main chat area has messages, prompt input, agent response, technical output.
- [ ] Right sidebar has result panel, workflow status, SQL panels, schema summary, user query box, Safety Report, Yes/No controls, code input, and result/error panel.
- [ ] UI displays high-risk confirmation code from backend.
- [ ] UI has input for 4-digit code.
- [ ] UI calls `/query/execute` only after user decision.

## Profile/Security Checks
- [ ] Model profile flow stores raw API key into `.env` only and `api_key_env` into JSON.
- [ ] Database profile flow stores raw password into `.env` only and `password_env` into JSON.
- [ ] Overwrite profile requires confirmation.
- [ ] API responses mask secrets.
- [ ] Logs/audit redact secrets.
- [ ] Agent connected DB remains read-only.
- [ ] User query box remains user-controlled and executes according to credential permission after safety check/confirmation/audit.
- [ ] `manual_write_enabled` does not silently block user query execution unless explicitly configured as a future policy.
